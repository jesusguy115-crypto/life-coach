# 建议卡协议

Python 3 标准库生成独立、离线的 HTML；正文静态可见。JavaScript 只用于下载 PNG，即使预览禁止脚本也能阅读或截图。没有打卡、输入框、复盘填写和本地存储。

输入 UTF-8 JSON：
```json
{
  "title": "先给眼前的问题一点空间",
  "situation": "一句简短的处境回应，不暴露非必要隐私。",
  "advice": ["一条贴合当前处境、可理解的建议。"],
  "closing": "一句温和、克制的提醒。",
  "method": "第十章：观察对未来的担忧，将注意力带回当下。",
  "experience": "从 cases.json 选择一条可核对的人物经历，说明怎样应用或主观受益。",
  "basis": "注明原书观点、案例和本 skill 改编的区别。",
  "sources": [],
  "example": false
}
```

必需 title（最多60字符）、situation（200）、advice（1–3项，每项220）、closing（100）、basis（300）、method（120）、experience（220）。sources 最多4项，每项含 label 和 HTTP(S) url；涉及人物经历必须带对应已核验来源。假设案例用 example=true。全卡宜控制在250–450个中文字内，不必凑满条数。

书名与作者固定印在卡面和 PNG，method、experience 也直接可见，不能只写到 JSON 或折叠依据。method 必须对应 当前能力卡 的原书方法和章节；advice 必须是这个方法在本情境的具体运用，不能是通用建议贴标签。experience 区分应用、主观受益、推荐，人数不能混算。basis 说明哪些练习是本 skill 的改编。

运行 resources/scripts/render_card.py <输入.json> --out <输出目录>。返回新 HTML 和 JSON 的绝对路径，既有文件不覆盖。日期按 Asia/Shanghai 的 UTC+8 标注，仅代表生成时间，不代表用户承诺日期。

用户可以点击“保存这张建议卡”下载 PNG，也可保留 HTML 或截图。页面有轻微入场动效，支持减少动态效果偏好。不要求填写、完成、签到或同意建议。若只有关键追问还没有充分建议，可以暂不生成。

## 内容范围
建议卡只承载内在干扰与学习过程建议。禁止运动动作、技术训练、岗位操作或其他领域技术指令；不用落点、弧线、手肘、握拍等指导包装心理方法。原书技术案例仅作出处解释，不转写成用户练习。


## 两块内容与金句（优先于旧字段示例）
卡面固定两块：01 给你的建议（情境、基于书中方法的建议、方法出处）；02 书中金句（本次相关短句、中文书名、章节、译文标记）。人物经历放小字来源注记，不成为第三个主板块。旧 closing 字段只为兼容保留，不显示，不替代金句。
新增必填字符串 quote（中文金句，最多160字符）、original（已核对的英文原句，最多400字符）、locator（章节和所用文件页码，最多200字符）、translation（最多100字符）。HTML和导出PNG均显示金句和归属。
选句必须简练、有独立表达力量，与本次建议有直接关系；不为凑金句截断条件或扭曲上下文。必须对照可访问原文，原句、位置和译文一起记录；不能凭记忆编写、不能把自己的概括加引号。中文正式译本未经核对时，translation 写“据英文原文自译，非中文版原句”。只有核验了译本及译者/版次，才能声称中文原句。单卡一条短句；不要批量输出原书金句集。完整PDF尚未核验不妨碍核对具体句子，但不得声称来自已核实完整版本。找不到对应可核验金句时，先交文字，明确卡片待补原文，禁止伪造或用无关句子凑卡。
已核对的习惯主题示例：Habits are statements about the past, and the past is gone. 所用87页重排PDF第42页、第6章。自译：习惯说的是过去，而过去已经过去了。适合旧习惯不等于不可改变的身份；不可解释为忽略过去或不必练习。
